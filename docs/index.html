MedRAG Ops

A medical question-answering service built on NIH's MedQuAD collection, with the MLOps loop around it: versioned data, tracked experiments, a gated model registry, CI/CD, monitoring and automated retraining.

How a model gets to production

  1. Data: dvc repro downloads MedQuAD (CC BY 4.0) and the TREC 2017 LiveQA-Med judgements, then builds 28,844 passages and three eval sets.
  2. Train: every candidate retriever (BM25, a corpus-trained LSA model, pretrained bge-small, and hybrids) is evaluated and logged to MLflow; the best on the validation split becomes the challenger.
  3. Gate: the challenger and the current champion are both re-scored on held-out real consumer questions; it is promoted only if it is better and passes the guardrails.
  4. Deploy: the champion is baked into a Docker image, smoke-tested under 512 MB, pushed to GHCR and rolled out on Render.
  5. Monitor: every request is logged; a daily job checks query drift, retrieval confidence and latency, and triggers retraining when production questions stop looking like the evaluation set.
